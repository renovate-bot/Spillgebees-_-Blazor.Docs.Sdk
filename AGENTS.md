# Blazor.Docs.Sdk: Project Agent Instructions

## Project Overview

**Spillgebees.Blazor.Docs.Sdk** is a shared Razor Class Library NuGet package that provides everything needed to build and deploy documentation sites for Spillgebees Blazor component libraries. Each component repo (Blazor.Map, Blazor.RichTextEditor, etc.) hosts its own docs site using this SDK.

## Architecture

### Solution structure

```text
Blazor.Docs.Sdk.slnx                                      # XML solution (root)
├── src/Spillgebees.Blazor.Docs.Sdk/                       # Razor Class Library (NuGet package)
│   ├── Components/                                        # Shell layout, ExampleView, ApiDoc, etc.
│   ├── Navigation/                                        # NavSection, NavPage, ApiReferenceNav models
│   ├── Build/                                             # MSBuild-time source extraction, API manifest generation, resource locator
│   └── wwwroot/                                           # Generated by Vite: CSS, JS bundle, fonts (Schibsted Grotesk, Hanken Grotesk, Inter, JetBrains Mono; all variable)
├── src/Spillgebees.Blazor.Docs.Sdk.Assets/                # TypeScript/Vite build -- compiles CSS/JS assets into wwwroot
└── tests/Spillgebees.Blazor.Docs.Sdk.Tests/               # TUnit + bUnit tests
```

### SDK components

- **DocSite**: root layout: top bar, sidebar, mobile drawer, on-this-page rail, search; owns theme selection
- **DocSearch**: command palette (`Ctrl`/`Cmd`+`K`, `/`), ranked by `DocSearchIndex`
- **OnThisPage**: sticky heading rail with `IntersectionObserver` scroll spy
- **ExampleView**: live component + extracted source; preview/source/split modes, viewport clamps
- **ApiDoc**: generated API reference with member filtering, collapsible groups, deep links
- **CodeBlock**: syntax-highlighted code with a numbered gutter, soft-wrap toggle, file tabs (file picker past four files) and copy button
- **ThemeToggle** / **ThemePicker**: colour scheme preference / theme family
- **DocIcon**: shared inline icon set

### Code block layout

The line-number gutter is a **sibling** of the scrolling `<pre>`, not a pseudo-element
inside it: inside, a long line scrolls underneath the numbers. Lines are `display:
inline` and separated by real newline text nodes so that selecting the code by hand
copies with its line breaks; block-level line spans swallow the newlines.

Soft wrap is a visitor preference on `<html data-docs-code-wrap>`, so every block agrees
and each toggle can render its state from CSS alone. When wrapping, gutter cell heights
are synced from JS: a logical line can span several rows, and the row count has to come
from rounding the union box height; `getClientRects()` returns one rect per child inline
fragment, not per line box.

Whether a block shows file tabs or the file picker is decided in JS from the tab strip's
overflow (`fitCodeTabs`). Don't move it to a container query: containment makes the bar the
containing block for the picker's `position: fixed` click-away scrim.

### Theming

Two independent axes, written as attributes on `<html>` by the TypeScript module:
`data-docs-theme` (palette + type family) and `data-docs-scheme` (`light`/`dark`).

The stylesheet is layered: `_tokens.scss` declares the public `--docs-*` contract,
`themes/*.scss` supply colour tokens, and `_base`/`_chrome`/`_content`/`_widgets`
contain structure only: **no literal colour, font, radius or shadow values**. Keep it
that way: anything hard-coded in a structural partial cannot be themed.

Accent steps are named for contrast, not lightness: `--docs-accent-strong` has *more*
contrast against the background than `--docs-accent`, which means it is lighter in dark
schemes and darker in light ones.

### Build-time infrastructure

- **Source extraction** — MSBuild targets (running before `AssignTargetPaths`) discover `ExampleView<TComponent>` references, locate source files, and embed them as assembly resources with `SourceEmbed:{FullTypeName}:{FileName}` logical names
- **API manifest generation** — MSBuild targets process XML doc files + reflection into a JSON manifest embedded as a resource with `ApiManifest:{AssemblyName}` logical names
- **Runtime resource discovery** — `EmbeddedResourceLocator` searches across all loaded assemblies to find embedded resources, resolving the mismatch where targets embed into the docs assembly but runtime code references the library assembly

### .NET target

The library targets `net10.0` (configured in `src/General.targets`).
ASP.NET Core package versions are pinned in `src/Directory.Packages.props`.

## Testing

- **Framework:** TUnit + AwesomeAssertions + bUnit
- **Run tests:** `dotnet test --solution Blazor.Docs.Sdk.slnx`
